SECTION 1: INTRODUCTION TO UVM
================================================================================

UVM is an open-source, class-based verification methodology used in the semiconductor
industry for functional verification of digital designs. It's built on SystemVerilog
and provides a standardized framework for creating reusable, scalable verification
environments.

Key Benefits:
- Reusability across different projects
- Improved productivity and quality
- Standardized verification metrics
- Comprehensive base class library
- Large ecosystem of tools and methodologies

SECTION 2: UVM BASE CLASSES AND HIERARCHY
================================================================================

The UVM methodology is built around the following core base classes:

1. uvm_object
   - Base class for all UVM objects
   - Provides fundamental functionality like printing, copying, comparing
   - Methods: get_name(), get_type_name(), print(), copy(), compare()

2. uvm_component
   - Extends uvm_object
   - Hierarchical structure for verification environment
   - Has parent-child relationships
   - Methods: get_parent(), get_child(), find_all()

3. uvm_env (Environment)
   - Container for agents and other verification components
   - Builds and configures the verification environment
   - Methods: build_phase(), connect_phase()

4. uvm_agent (Agent)
   - Contains drivers, monitors, sequencers
   - Can be active (drives stimuli) or passive (monitors only)
   - Methods: build_phase(), connect_phase()

5. uvm_sequencer (Sequencer)
   - Generates and sends sequences to drivers
   - Manages sequence execution
   - Methods: start_item(), finish_item(), get_next_item()

6. uvm_driver (Driver)
   - Receives transactions from sequencer
   - Drives stimulus to DUT via interfaces
   - Methods: run_phase()

7. uvm_monitor (Monitor)
   - Observes interface signals
   - Collects coverage and transactions
   - Methods: run_phase()

8. uvm_scoreboard (Scoreboard)
   - Compares expected vs actual results
   - Tracks test progress and results
   - Methods: write()

9. uvm_sequence (Sequence)
   - Defines a series of transactions
   - Base class for creating custom sequences
   - Methods: body()

10. uvm_transaction (Transaction)
    - Data container for stimulus and response
    - Represents single unit of stimulus
    - Methods: copy(), compare(), print()

SECTION 3: UVM PHASES - TEST EXECUTION FLOW
================================================================================

UVM uses a phased execution model to organize verification activities:

1. BUILD PHASE
   - Creates and configures components
   - Builds hierarchy
   - Creates default sequences
   - Called once per simulation

2. CONNECT PHASE
   - Establishes connections between components
   - Creates port/export connections
   - Configures interfaces
   - Called after build_phase

3. END_OF_ELABORATION_PHASE
   - Final configuration adjustments
   - Environment validation
   - Called after connect_phase

4. START_OF_SIMULATION_PHASE
   - Pre-simulation setup
   - Print configuration messages
   - Called before run_phase

5. RUN_PHASE (Main Phase)
   - Longest phase where test executes
   - Sequences generate transactions
   - Drivers apply stimulus
   - Monitors collect responses
   - Default length: infinite (stopped by objection)

6. EXTRACT_PHASE
   - Extract coverage and prediction data
   - Prepare reports
   - Called after run_phase

7. CHECK_PHASE
   - Compare predictions with actual results
   - Perform final checks
   - Called after extract_phase

8. REPORT_PHASE
   - Generate test reports
   - Print statistics
   - Called after check_phase

9. FINAL_PHASE
   - Clean up resources
   - Close files
   - Called last

SECTION 4: KEY UVM CONFIGURATION MECHANISMS
================================================================================

1. UVM_CONFIG_DB (Configuration Database)
   - Global configuration repository
   - Hierarchical configuration passing
   - Methods:
     * set(uvm_object scope, string name, <T> value)
     * get(uvm_object scope, string name, <T> value)

2. FACTORY PATTERN
   - Create objects by type name
   - Override object creation
   - Methods:
     * uvm_factory::get().create_component_by_name()
     * uvm_factory::get().create_object_by_name()

3. OVERRIDES AND SUBSTITUTION
   - Replace components with alternatives
   - Type overrides
   - Instance overrides

SECTION 5: UVM COMMUNICATION MECHANISMS
================================================================================

1. TLM (Transaction Level Modeling)
   - Port-based communication
   - Analysis ports for broadcasting
   - Request-response communication

2. UVM_TLM_ANALYSIS_FIFO
   - Stores transactions for analysis
   - Thread-safe operation
   - Methods: write(), read(), try_peek()

3. TLM PORTS
   - uvm_put_port: Send transactions
   - uvm_get_port: Receive transactions
   - uvm_analysis_port: Broadcast transactions

SECTION 6: COMMON UVM METHODS AND UTILITIES
================================================================================

OBJECT METHODS:
- set_name()          : Set object name
- get_parent()        : Get parent component
- get_full_name()     : Get hierarchical name
- create()            : Create new instance
- clone()             : Deep copy
- copy()              : Copy data
- compare()           : Compare objects
- print()             : Print object contents

COMPONENT METHODS:
- build_phase()       : Construct components
- connect_phase()     : Connect ports/exports
- end_of_elaboration_phase()  : Final configuration
- start_of_simulation_phase() : Pre-simulation setup
- run_phase()         : Main test execution
- raise_objection()   : Request phase continuation
- drop_objection()    : Allow phase completion

SEQUENCE METHODS:
- body()              : Define sequence behavior
- start()             : Start sequence on sequencer
- pre_body()          : Execute before body
- post_body()         : Execute after body
- wait_for_grant()    : Wait for sequencer grant
- send_request()      : Send transaction request

DRIVER METHODS:
- get_next_item()     : Get transaction from sequencer
- item_done()         : Signal transaction completion
- run_phase()         : Driver execution

MONITOR METHODS:
- run_phase()         : Monitor bus activity
- write()             : Pass transactions to analysis ports

COVERAGE METHODS:
- sample()            : Record coverage samples
- get_coverage()      : Get coverage percentage
- get_inst_coverage() : Get instance coverage

           |    +-- uvm_monitor
           |
           +-- uvm_agent (passive)
           |    +-- uvm_monitor
           |
           +-- uvm_scoreboard

Each component has specific responsibilities and communicates via:
- TLM analysis ports
- Configuration database
- Events and triggers
